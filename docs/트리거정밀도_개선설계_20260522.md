### 상세 평가

#### A. 차선 기반 TTC 필터링

현재 `compute_all_ttc()`는 모든 트랙 쌍 O(n²)을 계산. 고속도로 CCTV에서 인접 차선 차량은 2D 좌표상 가깝지만 실제로는 횡방향 3~4m 떨어져 있어 충돌 가능성 없음.

**핵심 아이디어**: 두 차량의 bbox가 이동 방향 기준 **횡방향(X축)으로 충분히 겹칠 때만** TTC 계산.

구현 위치: `ttc_calculator.py:compute_all_ttc()` 또는 `trigger_detector.py:_check_ttc()`

기존 코드에서 bbox는 `[x1, y1, x2, y2]` 형식으로 `_track_history`에 이미 저장됨. X축 겹침 비율 계산은 즉시 가능.

**한계**: 고속도로 CCTV 시점에 따라 차선이 Y축과 평행하지 않을 수 있음 → 완벽하진 않지만 70%+ 효과 기대.

#### B. 궤적 이상 탐지

TTC 대신 차량 궤적의 **상대적 변화**로 이상 감지:
- 급정거: 속도 변화율 (현재 T2에 있지만 임계값이 -3.0 m/s²로 낮음)
- 급차선변경: bbox 중심 X축 이동이 bbox 폭 대비 큰 경우
- 충돌 후 산개: 여러 트랙이 동시에 비정상 방향 전환

현재 `_speed_history`와 `_track_history`에 모든 데이터 있음. 추가 데이터 불필요.

**한계**: "급정거"의 기준이 픽셀 속도여서 원근 효과 영향. 프레임 상단(먼 곳)은 실제 급정거도 픽셀 변화 작음. 하지만 **변화율** 기준이라 절대값보다 안정적.

#### C. 다중 트리거 합의

현재: T1 단독 발화 → 즉시 녹화 시작
개선: N초 윈도우 내 M종 이상 트리거 동시 발화 시에만 녹화

실제 사고 진행 패턴:
```
급감속(T2) → TTC 급락(T1) → 정지(T3) → [충돌] → 후속 차량 동시 감속(T5)
```

단일 T1만으로는 정상 교통에서도 상시 발생. 하지만 T1+T2 또는 T1+T5가 5초 내 동시 발생하면 실제 사고 가능성 높음.

구현 위치: `trigger_detector.py` 상위 레벨 또는 `run_realtime.py`의 녹화 판정 로직

**한계**: 실제 사고 데이터 없이 합의 조건 설정이 어려움. 초기에는 느슨한 조건(2종 합의)으로 시작.

#### D. 호모그래피 캘리브레이션

`speed_estimator.py`에 이미 호모그래피 로딩 코드가 구현되어 있음:
```python
self._H: np.ndarray | None = None  # 3×3 homography matrix
```

하지만 **각 CCTV별 기준점 수동 지정** 필요:
- ITS CCTV 수천 대 → 전수 캘리브레이션 불가
- 모니터링 대상 카메라가 핫스팟 로테이션으로 변경됨
- 가장 정확하지만 운영 비용이 가장 높음

#### E. 임계값 강화

현재 설정 → 제안:
```
TTC_THRESHOLD:    3.0s → 2.0s (상위 6%만 통과)
TTC_STREAK_MIN:   2f  → 4f  (4초간 지속 위험)
TTC_MIN:          0.3s → 0.5s (bbox 근접 아티팩트 확대)
SEVERITY_GATE:    0.3  → 0.5  (상위 80% 통과)
COOLDOWN:        30s  → 60s  (연속 녹화 억제)
```

**한계**: 근본 원인(cross-lane 오탐)을 해결하지 않음. 임계값 올리면 실제 사고도 놓칠 수 있음.

#### F. 시각적 단서 활용

CPU 전용 환경에서 추가 모델 돌리기 어려움. 사고 학습 데이터도 없음. 장기 과제.

## 4. 단기 대책 구체 설계안

### 4-1. 방향 A: 차선 기반 TTC 필터링

#### 문제

```python
# ttc_calculator.py:91 — 현재
for tid_a, tid_b in combinations(active_ids, 2):
    ttc = compute_ttc(tracks[tid_a], tracks[tid_b])  # 모든 쌍
```

6대 차량 → 15쌍 계산. 이 중 같은 차선은 2-3쌍. 나머지 12-13쌍은 cross-lane 오탐 후보.

#### 해법

두 차량의 **bbox X축 범위 겹침 비율**로 same-lane 여부를 추정:

```
차량A  [x1a ====== x2a]
차량B     [x1b ====== x2b]
         ↑──겹침──↑

X-overlap = max(0, min(x2a, x2b) - max(x1a, x1b))
overlap_ratio = X-overlap / min(width_a, width_b)
```

- `overlap_ratio > 0.3` → 같은 차선 (TTC 계산 대상)
- `overlap_ratio <= 0.3` → 다른 차선 (TTC 계산 건너뜀)

#### 수정 위치: `ttc_calculator.py`

`compute_all_ttc()` 함수에 lane_filter 추가:

```python
def _is_same_lane(track_a_hist, track_b_hist, overlap_threshold=0.3):
    """최근 bbox의 X축 겹침으로 같은 차선 여부 추정."""
    ba = track_a_hist[-1]["bbox"]  # [x1, y1, x2, y2]
    bb = track_b_hist[-1]["bbox"]
    
    x_overlap = max(0, min(ba[2], bb[2]) - max(ba[0], bb[0]))
    w_a = ba[2] - ba[0]
    w_b = bb[2] - bb[0]
    min_w = min(w_a, w_b)
    
    if min_w <= 0:
        return False
    return (x_overlap / min_w) > overlap_threshold


def compute_all_ttc(tracks, lane_filter=True):
    results = []
    active_ids = [tid for tid, h in tracks.items() if len(h) >= 2]
    
    for tid_a, tid_b in combinations(active_ids, 2):
        if lane_filter and not _is_same_lane(tracks[tid_a], tracks[tid_b]):
            continue  # 다른 차선 → 건너뜀
        ttc = compute_ttc(tracks[tid_a], tracks[tid_b])
        if ttc is not None:
            results.append({"track_a": tid_a, "track_b": tid_b, "ttc": ttc})
    
    results.sort(key=lambda x: x["ttc"])
    return results
```

#### 예상 효과

v3 데이터 기준 TTC < 0.5s 348건 중 **~80%가 cross-lane**으로 추정 (인접 차선 bbox 근접). 이 필터로 T1 트리거 482건 → **~100건** 예상 (80% 감소).

#### 리스크

- 고속도로 합류구간/분기구간에서 차선 변경 중인 차량은 X-overlap이 높을 수 있음 → 오탐 유지되나 이는 실제 위험 상황에 가까움
- CCTV 시점이 극단적 대각선인 경우 X축 ≠ 횡방향 → 효과 감소. 하지만 대부분의 고속도로 CCTV는 주행 방향과 대략 정렬됨

### 4-3. 방향 C: 다중 트리거 합의 (기본)

#### 문제

T1(TTC) 단독 발화 → 즉시 녹화. 정상 교통에서 T1은 분당 ~9건 발생하므로 불필요 녹화 과다.

#### 해법

녹화 시작 조건을 **T1 단독 → 합의 기반**으로 변경:

```
[즉시 녹화] (단독 발화 충분)
  - T5 (다수 동시 감속 3대+)

[합의 필요] (5초 윈도우 내 2종 이상)
  - T1(TTC) + T2(급감속)
  - T1(TTC) + T3(정지차량)
  - T1(TTC) + T5(동시감속)
  - T2(급감속) + T3(정지차량)

[녹화 안 함] (단독 발화 무시)
  - T1 단독
  - T3 단독
  - T6 단독 (속도분산)
```

#### 수정 위치: `run_realtime.py` (녹화 판정 부분)

기존:
```python
# _handle_trigger에서 모든 트리거 → 녹화 시작
if trigger.severity < SEVERITY_GATE:
    return
# → 녹화 시작
```

변경:
```python
# 트리거 윈도우 버퍼
_trigger_window: list[TriggerEvent] = []
CONSENSUS_WINDOW_SEC = 5.0

INSTANT_RECORD_TYPES = {"T5"}           # 단독 즉시 녹화
CONSENSUS_REQUIRED_TYPES = {"T1", "T3"} # 합의 필요
CONSENSUS_MIN_TYPES = 2                 # 최소 2종

def _should_record(trigger, trigger_window):
    # 즉시 녹화 유형
    if trigger.type in INSTANT_RECORD_TYPES:
        return True
    
    # 윈도우 정리
    cutoff = trigger.timestamp - CONSENSUS_WINDOW_SEC
    trigger_window[:] = [t for t in trigger_window if t.timestamp > cutoff]
    trigger_window.append(trigger)
    
    # 윈도우 내 트리거 유형 수
    types_in_window = {t.type for t in trigger_window}
    if len(types_in_window) >= CONSENSUS_MIN_TYPES:
        return True
    
    return False
```

#### 예상 효과

v3 데이터에서:
- T1 단독 482건 → 합의 통과 건수는 T2/T3/T5 동시 발화 여부에 의존
- T2(급감속) 0건, T3(정지) 8건, T5(동시감속) 0건이 v3에서 발생
- T1 + T3 동시 5초 윈도우 = 매우 드뭄
- **녹화 건수: 10건 → 0-1건 예상 (90%+ 감소)**

#### 리스크

- 실제 사고 시에도 T1만 먼저 오고, T2/T3는 수초 뒤 올 수 있음 → 윈도우 크기 5초로 커버
- T5(다수 동시 감속)는 진짜 위험 상황이므로 단독 즉시 녹화 유지
- T7(주기적)은 녹화 대상이 아니므로 무관

### 구현 우선순위 및 조합 전략

**Phase 1 (즉시)**: A + E 동시 적용

- A(차선 필터)로 TTC 계산 대상 80% 감소
- E(임계값)로 나머지 중 TTC < 0.5s, streak < 4f 추가 제거
- 예상: 482건 T1 → **20-30건** (95% 감소)

**Phase 2 (Phase 1 효과 검증 후)**: C 추가 적용

- Phase 1 후에도 T1 단독 오탐이 남으면 합의 로직 추가
- 예상: 녹화 10건 → **0-1건** (오탐 거의 제거)

**Phase 1+2 종합 예상**:

| 지표 | 현재 (v3) | Phase 1 후 | Phase 1+2 후 |
|------|-----------|-----------|-------------|
| T1 트리거/시간 | ~570건 | ~30건 | ~30건 |
| 녹화/시간 | ~12건 | ~2건 | ~0.5건 |
| **정밀도** | 0% | 미지수 | **목표 50%+** |
| 재현율 | 미지수* | 미지수* | 미지수* |

*재현율은 실제 사고 발생 시에만 측정 가능. ITS API 사후 대조로 검증.

## 부록: v3 오탐 구조 분석

### 왜 severity가 높은데 정상인가

severity = `1.0 - TTC / TTC_THRESHOLD` 공식에서:
- TTC=0.3s → severity = 1.0 - 0.3/3.0 = 0.90
- TTC=0.5s → severity = 1.0 - 0.5/3.0 = 0.83

severity는 **TTC의 역함수**일 뿐, 실제 위험도와 무관. TTC 자체가 2D 픽셀 공간에서 오산이므로 severity도 오산.

### 왜 연속 프레임 필터(streak)로도 안 되는가

인접 차선 차량이 비슷한 속도로 주행하면 bbox 거리가 **수십 프레임간 안정적으로 유지**. 즉 streak=2는 물론 streak=4도 쉽게 충족.

**핵심**: 문제는 연속성이 아니라 **차선 구분 부재**. 다른 차선 차량 쌍 자체를 TTC 계산에서 제외해야 함 (방향 A).
