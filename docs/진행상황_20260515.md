## 1. 시스템 개요

CCTV 영상에서 교통사고를 자동으로 탐지하고 분석하는 시스템.
핵심 아이디어: **이상징후 탐지(AI) → 사고 확인(API)** 2단계 구조.

```
CCTV 영상 실시간 분석
       ↓
이상징후 감지 (AI 모델)
       ↓
돌발상황 API로 사고 여부 확인
       ↓
확인된 사고 영상 자동 저장 + 학습 데이터 축적
```

기존 방식(API 알림 수신 후 녹화)은 사고 발생과 알림 사이 시간차로 인해
사고 순간을 놓치는 문제가 있었음. AI가 먼저 이상징후를 포착하고,
API로 실제 사고 여부를 확인하는 방식으로 해결.

### 저장소 역할 요약

| 저장소                     | 기술           | 저장 대상                          | 용도                                       |
| -------------------------- | -------------- | ---------------------------------- | ------------------------------------------ |
| **VectorDB ①** 궤적 패턴   | Qdrant/Milvus  | 차량별 궤적 시퀀스 임베딩          | 과거 유사 이상 패턴 검색 → 예측 보강       |
| **VectorDB ②** 장면 임베딩 | Qdrant/Milvus  | 프레임 단위 교통 장면 임베딩       | 정상 분포 학습, 이상도 거리 측정 (IF/LSTM) |
| **VectorDB ③** 사고 사례   | Qdrant/Milvus  | LLM 보고서 + 메타데이터 임베딩     | RAG: 유사 사례 검색 → LLM 분석 품질 향상   |
| **관계형 DB**              | PostgreSQL     | 사고 이력, 알림, 보고서, 성능 지표 | 통계/대시보드, 이력 조회, 모델 성능 추적   |
| **파일 스토리지**          | Expansion 15TB | 영상 원본, 키프레임, AI Hub 데이터 | 학습 데이터 원본, 증거 보존                |

### VectorDB ↔ 관계형 DB 연결 관계

```
관계형 DB                              VectorDB
───────────                            ─────────
incidents.incident_id ─── 1:N ───→ VDB① trajectory_embedding
                                       (incident당 관련 차량 궤적 N개)

incidents.incident_id ─── 1:N ───→ VDB② scene_embedding
                                       (incident 전후 프레임 임베딩 N개)

reports.embedding_id  ─── 1:1 ───→ VDB③ report_embedding
                                       (보고서 1건 = 임베딩 1개)

incident_vehicles     ─── 1:1 ───→ VDB① trajectory_embedding
.trajectory_embedding_id               (차량 1대 = 궤적 임베딩 1개)
```

**조회 흐름 예시:**
1. 새 이상징후 발생 → 특성벡터로 VDB① 검색 → 유사 궤적 과거 사례 ID 획득
2. 사례 ID로 관계형 DB 조회 → 당시 사고 유형/심각도/대응 이력 확인
3. VDB③에서 해당 사례 보고서 검색 → LLM에 few-shot 예시로 전달
4. LLM 보고서 생성 → 관계형 DB 저장 + VDB③ 임베딩 추가

### Track 3 — 실시간 자동 수집 (v4 가동 중)

사고 징조를 AI가 먼저 포착하면 그 즉시 녹화를 시작하는 온디맨드 방식.

- ITS API 2종 연동: 돌발상황(사고 확인) + CCTV(스트림 URL)
- 사고다발구간(핫스팟) 자동 선정 → 인근 CCTV 4대 동시 감시
- 녹화: 트리거 시점에 ffmpeg 시작, 3~5분 녹화, ITS API로 사고 확인

#### 버전 진화 이력 (2026-05-22)

| 버전 | 구조 | 결과 | 문제 |
|------|------|------|------|
| v1 | Ring Buffer (상시 녹화) | - | 디스크 과다 사용 |
| **v2** | OnDemand (트리거 시 녹화) | 55분: 트리거 167건, 녹화 4건, 보존 0건 | T1 TTC 오탐 과다 |
| **v3** | v2 + TTC필터 + 3단계보존 + 다중카메라 | 33분: 트리거 157건, 녹화 6건, 보존 0건 | **전부 오탐** (정상 교통) |

#### v3→v4 핵심 개선 (2026-05-22)

**근본 원인 진단**: TTC가 2D 픽셀 공간에서 모든 트랙 쌍 O(n²)을 계산 → 다른 차선 차량도 TTC 0.3~0.9s로 오산 → 정상 교통에서 상시 발화

**3중 방어 계층 구현**:

| 계층 | 방향 | 내용 | 효과 |
|:---:|------|------|------|
| 1 | **차선 필터** | bbox X-overlap > 30%인 쌍만 TTC 계산 | cross-lane 쌍 ~95% 제거 |
| 2 | **임계값 강화** | TTC 2.0s, streak 4f, TTC_MIN 0.5s, 쿨다운 60s | 아티팩트 추가 제거 |
| 3 | **다중 합의** | T1 단독 녹화 금지, 5초 내 2종+ 합의 필요 (T5만 즉시) | 단독 T1 차단 |

**실가동 비교 (v3 33분 vs v4 40분)**:

| 지표 | v3 | v4 | 감소율 |
|------|:---:|:---:|:---:|
| 트리거/시간 | ~285건 | **~42건** | **85%** |
| T1(TTC)/시간 | ~254건 | **~12건** | **95%** |
| 녹화/시간 | ~11건 | **0건** | **100%** |
| 오탐 녹화 | 6건(전부) | **0건** | - |

#### 3단계 보존 정책

```
트리거 → 녹화 → 종료 → ITS 확인
  ├─ ITS 사고 확인 → confirmed (영상 보존)
  ├─ ITS 미확인 + severity ≥ 0.7 → pending (재확인 3회×10분)
  └─ ITS 미확인 + severity < 0.7 → deleted
```

#### 현재 가동 상태 (2026-05-22)

#### 전국 363대 스케일업 (2026-05-22 설계·구현 완료)

## 3. 이상징후 탐지 엔진 — Level 0+1 구현 완료

### 기본 구조

4단계 탐지 모델을 병렬로 실행하고, 결과를 종합 판단.
단순한 규칙부터 시작해서 점진적으로 고도화.

```
영상에서 추출한 차량 데이터
    ├── Level 1: 규칙 기반 (급정거, 역주행 등)            ── 점수 ──┐
```

### Level 4: STGAE — 차량 관계 이상 탐지 모델

> 논문: "Anomaly Detection in Multi-Agent Trajectories for Automated Driving"
> (CoRL 2021, Gainer et al.)

#### 모델 선정 과정

Level 4에 쓸 "차량 관계 모델링" 후보를 조사한 결과:

| 모델      | 논문       | 코드 공개        | 이상탐지 전용 | 비고             |
| --------- | ---------- | ---------------- | ------------- | ---------------- |
| **STGAE** | CoRL 2021  | **완전 공개**    | **O**         | **채택**         |
| VT-Former | CVPRW 2024 | X (404)          | X (예측 전용) | 코드 없음        |

"좋은 논문"보다 **"지금 바로 쓸 수 있는 코드"**를 우선하여 STGAE를 채택.

#### STGAE란 무엇인가

STGAE = **S**patial-**T**emporal **G**raph **A**uto-**E**ncoder
(시공간 그래프 자동 인코더)

```
비유: 퍼즐 맞추기

  정상 주행 장면을 "퍼즐"이라고 생각하자.

  [학습]  정상 장면 수만 개를 퍼즐로 분해했다가 다시 맞추기를 반복.
          AI가 "정상 퍼즐은 이렇게 맞추면 된다"를 학습한다.

  [탐지]  새 장면이 들어오면 → 퍼즐로 분해 → 다시 맞추기 시도.
          정상이면 → 퍼즐이 잘 맞춰짐    → 이상 점수 낮음 ✓
          비정상이면 → 퍼즐이 안 맞춰짐  → 이상 점수 높음 ⚠️
                     "이런 패턴은 본 적 없는데?"

  핵심: 비정상 사례를 외우는 게 아니라,
        "정상이 어떤 것인지"를 학습해서 그에서 벗어나면 이상으로 판단.
```

#### 처리 흐름 (4단계)

```
[1단계] 그래프 구성 — 차량 관계를 지도로 그리기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CCTV 화면에 차량 5대가 보인다.
  각 차량을 점(노드)으로, 가까운 차량끼리 선(엣지)으로 연결.

    차량A ──── 차량B        이 "지도"를 매 프레임마다 만든다.
      │  \                  30프레임 분량(약 3초)을 묶으면
    차량C   차량D            시간에 따라 관계가 변하는
              │              "움직이는 지도"가 된다.
            차량E

  비유: 사람 5명이 방에 있을 때, 누가 누구 옆에 있는지
        관계도를 매초 그리는 것.


[2단계] 인코더 — 압축하기
━━━━━━━━━━━━━━━━━━━━━━━

  이 움직이는 지도(30프레임 × 5대)를 AI가 압축한다.
  "핵심 패턴"만 남기고 나머지는 버린다.

    30프레임 × 5대 × (x,y) = 300개 숫자
          ↓ 압축
    잠재 벡터 = 수십 개 숫자

  비유: 3분짜리 교통 상황을 한 줄로 요약하는 것.
        "5대가 같은 방향, 비슷한 속도, 일정 간격으로 주행 중"


[3단계] 디코더 — 복원하기
━━━━━━━━━━━━━━━━━━━━━━━

  압축된 요약에서 원래 궤적을 복원 시도.

    잠재 벡터 (수십 개 숫자)
          ↓ 복원
    30프레임 × 5대 × (x,y) = 300개 숫자 (복원본)

  정상이면: 원본과 복원본이 거의 같다 → "이 패턴은 잘 안다"
  비정상이면: 원본과 복원본이 크게 다르다 → "이런 건 본 적 없다"


[4단계] 점수 — 재구성 오차 = 이상 점수
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  원본과 복원본의 차이를 숫자로 환산.

  정상 장면:
    원본: A→(100,200), B→(300,210), ...
    복원: A→(101,199), B→(299,211), ...
    차이: 평균 1.5px → 이상 점수 0.1 ✓

  사고 직전:
    원본: A→(100,200), B→(100,205), ...  ← 두 대가 수렴!
    복원: A→(105,210), B→(295,215), ...  ← "정상이면 이럴 텐데"
    차이: 평균 95px → 이상 점수 0.9 ⚠️
```

#### 왜 "정상만 학습"해도 되는가

```
비유: 맞춤법 검사기

  맞춤법 검사기는 "올바른 문장"만 학습한다.
  틀린 문장의 목록을 외우는 게 아니라,
  올바른 패턴을 학습해서 "이건 이상하다"를 판단한다.

  STGAE도 마찬가지:
  · 정상 주행 궤적 수십만 건을 학습
  · "차들이 이렇게 움직이면 정상이다"를 학습
  · 학습한 적 없는 비정상 패턴 → 복원 실패 → 높은 이상 점수

  장점: 비정상 데이터가 적어도 (또는 없어도) 학습 가능
  우리 데이터: AI Hub #71566 정상 96만건으로 바로 학습 시작 가능
```

#### 우리 시스템에서의 역할

```
Level 1 (규칙):   "차량 1대가 급정거했다"             → 개별 이상
Level 2 (통계):   "이 속도는 통계적으로 비정상"        → 통계 이상
Level 3 (시계열): "이 차의 궤적이 과거와 다르다"       → 시간 이상
Level 4 (STGAE):  "5대의 관계 패턴을 복원할 수 없다"   → 관계 이상
```

L1~L3은 차량을 **하나씩** 본다. STGAE는 **동시에 여러 대의 관계**를 본다.
3대가 각각 약간 감속 → L1은 "정상"이라고 판단 (급정거 아님).
STGAE는 "3대가 동시에 감속하면서 한 지점으로 수렴하는 패턴은 복원 불가" → 이상 판정.

#### 모델 상세

| 항목        | 값                         | 설명                                        |
| ----------- | -------------------------- | ------------------------------------------- |
| 모델 구조   | Graph Conv + GRU           | 공간(그래프) + 시간(순환) 처리              |
| 입력        | `[batch, time, agents, 2]` | 차량별 (x, y) 좌표 시퀀스                   |
| 학습 손실   | Bivariate Gaussian NLL     | 위치의 확률 분포로 재구성                   |
| 학습 데이터 | **정상 주행만**            | 비정상 라벨 필요 없음 (비지도)              |
| 추론 속도   | 수백 ms/장면               | ~30프레임, ~10대 기준. 슬라이딩 윈도우 운용 |
| 코드        | **PyTorch, 완전 공개**     | train/test/one-class 모드                   |

#### 우리 데이터와의 호환

```
우리 VisionPipeline 출력:     STGAE 입력:
  (frame, track_id, cx, cy)  →  [batch, time, agents, (x,y)]

변환 코드 (개념):
  for t in range(30):                     # 30프레임 윈도우
      for i, vehicle in enumerate(tracked_vehicles):
          tensor[t, i, 0] = vehicle.cx    # x 좌표
          tensor[t, i, 1] = vehicle.cy    # y 좌표
```

AI Hub #71566 데이터도 직접 사용 가능:
- `annotation[].bbox` → 차량 중심점 (cx, cy) 추출
- `정상/` 폴더 96만건 → 학습 데이터
- `비정상/` 폴더 94만건 → 검증/임계값 보정

#### 모델 비교 — 검토했던 후보들

|               | STGAE (채택)            | VT-Former               | DiffTAD                   |
| ------------- | ----------------------- | ----------------------- | ------------------------- |
| **원리**      | 현재를 복원 못하면 이상 | 미래를 예측 못하면 이상 | 노이즈 제거 실패하면 이상 |
| **코드**      | 완전 공개               | 없음 (404)              | 메인 미공개               |
| **논문 검증** | CoRL 2021 (검증 완료)   | CVPRW 2024 (예측만)     | 미출판                    |
| **이상탐지**  | 전용 설계               | 별도 설계 필요          | 전용 설계                 |
| **차량 관계** | 그래프로 직접 모델링    | 토큰으로 변환           | Transformer 내부          |
| **CPU 추론**  | 가능                    | 가능 (구현 시)          | 느림 (Diffusion)          |
| **장점**      | 즉시 사용 가능          | 소형 (13만 파라미터)    | AUC +26%                  |
| **단점**      | 2021년 모델             | 코드 없음               | 코드 없음, CPU 느림       |

VT-Former와 DiffTAD는 아이디어는 우수하나 코드가 없어 직접 구현해야 한다.
STGAE는 2021년 모델이지만 코드가 완전하고 이상탐지 전용 설계라 즉시 적용 가능.
향후 VT-Former나 DiffTAD 코드가 공개되면 STGAE와 앙상블하거나 교체 검토.

#### 향후 개선 경로

```
단기:  STGAE 그대로 적용
       → AI Hub #71566 정상 데이터로 학습
       → L1~L3 앙상블에 L4 점수 추가

중기:  PishguVe(GIN+Attention)의 그래프 구조를
       STGAE의 인코더에 이식 → 관계 표현력 강화

장기:  DiffTAD/VT-Former 코드 공개 시
       STGAE와 앙상블 또는 교체 검토
```
