## 전반 평가

강점: Layer0(수집)~Layer3(MLLM) 액티브 경로는 실제 동작하며, HLS 직접 다운로드(60GB/일·끊김0), 프리필터+YOLO+트리거(v4 다중합의), MLLM 보고서 생성이 PoC 수준에서 검증됨. 카메라별 독립 스레드 격리, 다중모드 graceful degradation, 트리거 쿨다운 등 방어 로직도 일부 존재. 약점: (1) 시스템이 '설계는 됐으나 미배선' 상태가 광범위함 — Layer4 예측 체인 전체(traffic_agg 0행→INTERVAL 버그→모델파일 없음), ML Level2~4(STGAE AUROC 0.49 포함), RAG/자기강화가 모두 엔진에 미통합. 따라서 다수의 'high' 발견은 즉시 장애가 아닌 '시한폭탄(향후 활성화 시 즉사)'임. (2) 24/7 무인운용 인프라 부재 — systemd/supervisor 없음, 디스크 보존정책 전무, ITS API 백오프/재시도 전무, 구조화 로깅·알림·메트릭 없음. (3) 액티브 경로의 데이터 무결성 구멍 — DuckDB 쓰기 실패 시 사고레코드 영구 손실, ITS 검증 실패 시 미확인 영상 삭제(false negative). (4) 비전 정확성의 근본 결함 — 캘리브레이션 부재로 속도/TTC가 픽셀단위(물리적 무의미)이며 이것이 T1/T2/T5/T6 트리거 전부를 오염. (5) 제안서-실제 갭 — MLLM 59초(제안서 15~30초의 2.6배), 키프레임 알고리즘 불일치(Bhattacharyya 명시했으나 미구현), 27% 자동생성 분모 불명확. 종합 건강도: 아키텍처 의도는 견고하나 '운영 준비도'는 낮음. 현재 운영 범위(액티브 4계층)에 한정하면 데이터손실·무인운용 리스크가 최우선이고, 미배선 모듈은 '활성화 게이트'를 걸어 안전하게 격리해야 함.

## 전략적 개선 (중장기)
