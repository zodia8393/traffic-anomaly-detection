## 1. 녹화 운용

### 연속 녹화 (현행)
```bash
cd src/layer0_data
PYTHONUNBUFFERED=1 nohup python3 record_hls_multi.py \
  --config /tmp/cameras_5routes.json --continuous \
  > /DATA/cctv_recording/record_continuous.log 2>&1 &
```
- 자정 기준 로테이션, 24h .ts → 자동 MP4 변환
- 상태: `/DATA/cctv_recording/watchdog_status.json`

### 무인 자동복구 (P3) — cron 등록됨
| 작업 | 주기 | 스크립트 |
|------|------|----------|
| 워치독(죽으면 재시작+디스크감시) | 5분 | `watchdog_recording.py` |
| 디스크 보존정리(21일 초과 삭제) | 매일 0:30 | `cleanup_recordings.py --keep-days 21` |

```bash
crontab -l | grep -E "watchdog|cleanup"   # 등록 확인
python3 cleanup_recordings.py --dry-run    # 삭제 대상 미리보기
python3 watchdog_recording.py              # 수동 헬스체크
```

### systemd 전환 (선택, sudo 필요) — ⚠️ 현행 nohup과 충돌 주의
```bash
# 1) 현행 nohup 녹화 중지 후 전환 (이중 녹화 방지)
pkill -f "record_hls_multi.py .*--continuous"
sudo cp deploy/cctv-recording.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now cctv-recording
systemctl status cctv-recording
```

```python
ok, events = client.fetch_incidents_status(event_type="acc", road_type="ex")
if not ok:   # API 미상 — '사고 없음'으로 단정 금지(오삭제 방지)
    ...
```
- 사고 체크: `python3 check_incidents_in_recording.py --radius 5`

## 4. ML 활성화 게이트 (P4)

- 기본 OFF. Level2~4 ML은 `config_new.ENABLE_ML_ENSEMBLE=True` + 전제조건(파일·AUROC≥0.6) 통과 시만 투표.
- **STGAE(AUROC 0.495)는 영구 격리** — 재학습으로 0.6+ 달성 후 `ML_MODEL_GATES["level4_stgae"]["enabled"]=True`.
```bash
python3 -m anomaly_engine.activation_gate   # 게이트 상태 진단
```
- Layer4 예측: `ENABLE_LAYER4_PREDICTION=True` + 모델 준비 후 활성화. 미활성 시 안전폴백.

## 5. 비전 캘리브레이션 (P5) — 카메라별 1회 작업

속도/TTC를 절대값(km/h)으로 쓰려면 카메라마다 호모그래피 필요(없으면 픽셀폴백=상대값).
```bash
# 영상에서 도로 위 4점 픽셀좌표 + 실세계좌표(m, 차로폭 3.5m 기준) 측정 후:
python3 layer1_vision/make_calibration.py --camera 경부선_원지동 \
  --img-pts "x1,y1 x2,y2 x3,y3 x4,y4" --world-pts "0,0 7,0 7,30 0,30"
# → configs/cameras/<카메라>.json (재투영 RMSE 1m 이내 권장)
```
- 미보정 시 `SpeedEstimator.is_calibrated == False` — 절대속도 신뢰 불가.
