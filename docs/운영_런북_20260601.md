### 무인 자동복구 (P3) — OpenClaw scheduler

2026-06-26부터 user crontab의 CCTV 항목은 주석 처리된 migration 기록만 남고, 실제 실행은 OpenClaw cron이 담당한다.

| OpenClaw job | 주기 | 스크립트 |
|------|------|----------|
| `migrated-recording-watchdog` | 5분 | `watchdog_recording.py` |
| `migrated-incident-logger` | 5분 | `incident_logger.py --once` |
| `migrated-recording-cleanup` | 매일 0:30 | `cleanup_recordings.py --keep-days 21` |
| `cctv-recording-daily-status` | 매일 20:55 | `recording_status_report.py` |

```bash
~/.openclaw/bin/openclaw cron list --json  # enabled/status/최근 실행 확인
crontab -l | grep MIGRATED_TO_OPENCLAW     # migration 기록 확인(실행 항목 아님)
python3 cleanup_recordings.py --dry-run    # 삭제 대상 미리보기
python3 recording_status_report.py --stdout # 읽기 전용 상태 확인
```

`watchdog_recording.py` 직접 실행은 recorder를 재시작할 수 있으므로 단순 상태 점검 용도로 실행하지 않는다.

### recorder 소유권과 systemd fallback

2026-07-10 현재 recorder는 OpenClaw watchdog이 관리하며, `cctv-recording.service`는 enabled이지만 inactive인 fallback이다. recorder 프로세스가 이미 실행 중일 때 systemd 서비스를 함께 시작하면 이중녹화가 발생할 수 있다.

```bash
pgrep -af record_hls_multi.py                # 현재 recorder 확인
systemctl is-active cctv-recording.service   # fallback 서비스 상태
systemctl status cctv-recording.service      # unit 상세
tail -f /DATA/cctv_recording/record_continuous.log
```

systemd를 다시 primary owner로 전환하려면 OpenClaw watchdog 중지, 기존 recorder 종료, unit `daemon-reload`, 서비스 시작을 한 번의 승인된 작업으로 수행한다. 운영 중에는 임의로 `restart`하지 않는다.
> **주의**: ffmpeg/ffprobe가 `~/.local/bin`에 있어 서비스에 `Environment=PATH=...`
> 필수 (systemd 최소 PATH엔 없음). 서비스 파일: `deploy/cctv-recording.service`.
